Crie uma implementação completa (Java + XML) de uma tela chamada "OpenTicket" que permita ao usuário abrir um chamado composto por texto (obrigatório) e uma imagem opcional. Antes de enviar o chamado, o app deve verificar se o departamento do usuário logado permite a abertura de chamados (campo `AcceptTicket` do model `Department`). Se a verificação indicar que não é permitido, o app deve bloquear o envio e exibir um diálogo claro dizendo ao usuário para contatar o suporte técnico.

Gere os arquivos separados conforme listados e escreva comentários explicando os pontos configuráveis (baseURL, origem do `userSourceId`, como ativar autenticação). Use AndroidX, Retrofit+OkHttp+Gson, Glide para preview, e LiveData/ViewModel para lógica. Use Java (não Kotlin) e XML (não Compose).

Contexto e endpoints (usar exatamente estes caminhos / nomes)
- Base URL default para emulador: `ApiConfig.BASE_URL = "http://10.0.2.2:5000"`
- `GET /departments/{id}` — obtém `Department` JSON; modelo inclui `bool AcceptTicket` (nome exato).
- `POST /tickettransactions/upload` — multipart/form-data: `file` (imagem opcional), `userSourceId` (int), `userTargetId` (int; enviar 0 quando não atribuído), `ticketId` (int), `body` (string).
- `POST /tickettransactions` — fallback JSON: `CreateTicketTransactionDto` { userSourceId:int, userTargetId:int, ticketId:int, body?:string, attachBase64?:string }.
- Observação: `userSourceId` vem do usuário logado (SessionManager / SharedPrefs / objeto retornado no `POST /login`). Documente isso no código.

2. `Activity` Java: `com.example.app.ui.OpenTicketActivity` (`OpenTicketActivity.java`)
   - Infla `activity_open_ticket.xml`.
   - Recupera `userSourceId` (usuário logado) e `ticketId` (opcional) de onde o app mantém sessão; coloque comentários indicando onde ajustar.
   - Inicializa `OpenTicketViewModel` via `ViewModelProvider`.
   - Implementa `ActivityResultLauncher` para `Intent.ACTION_GET_CONTENT` com tipo `"image/*"`.

   - Ao clicar `btn_submit`: validar `edittext_body` (não vazio). Em seguida chamar `viewModel.checkDepartmentAndSubmit(userSourceId, ticketId, useBase64Flag)`.
   - Observa LiveData: `isLoading` (mostrar/ocultar `ProgressBar`), `errorMessage` (mostrar `Toast`/Dialog), e `successDto` (mostrar `attachUrl` em `text_result` e botão abrir URL com `Intent.ACTION_VIEW`).

3. `ViewModel` Java: `com.example.app.viewmodel.OpenTicketViewModel` (`OpenTicketViewModel.java`)
   - LiveData/MutableLiveData: `imageUri:MutableLiveData<Uri>`, `body:MutableLiveData<String>`, `isLoading`, `errorMessage`, `successDto`.
   - Método público `checkDepartmentAndSubmit(int userSourceId, int ticketId, boolean useBase64)`:
     - Ler `deptId` do usuário logado (SessionManager ou injeção; documente).
     - Chamar `ApiService.getDepartment(deptId)` (Retrofit `Call<Department>`).
       - Se success e `AcceptTicket == true` → chamar `submit(...)` (multipart ou base64).
       - Se success e `AcceptTicket == false` → postar `errorMessage` / emitir evento para Activity abrir `AlertDialog` com mensagem: “Seu departamento não permite abertura de chamados. Contate o suporte técnico.” NÃO prosseguir com upload.
       - Se failure (rede/500/timeout) → postar `errorMessage` e expor opção de retry (LiveData ou callback).
   - Métodos internos:
     - `submitMultipart(...)` — se `imageUri` não nulo:
       - Usar `ImageUtils.compressAndResizeBitmap(...)` para garantir abaixo de 5 MB (ou reduzir para max width 1280).
       - Criar `MultipartBody.Part` para `file` e `RequestBody` para `userSourceId`, `userTargetId=0`, `ticketId`, `body`.
       - Chamar `ApiService.uploadTicketTransaction(...)` com Retrofit `enqueue`.
     - `submitBase64(...)` — ler bytes via `ImageUtils.readBytesFromUri`, converter para base64 com prefixo `data:<mime>;base64,`, montar `CreateTicketTransactionDto` e chamar `ApiService.createTicketTransaction(...)`.
     - Se não houver imagem selecionada: usar JSON endpoint (`createTicketTransaction`) sem `attachBase64` (ou com null).
   - Atualizar LiveData conforme resposta: `isLoading`, `successDto`, `errorMessage`.
